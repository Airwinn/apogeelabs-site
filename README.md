# Apogee Labs site

Static, zero-dependency, relative-URL. No build step: what's in the repo is
what ships. Push to GitHub, enable Pages (Settings → Pages → Deploy from
branch → `main` / root), done. Cloudflare Pages works the same way — point it
at the repo, leave the build command empty and the output directory as `/`.

```
index.html          hero + one pinned section per app
marge/ notch/       device-aware smart links (App Store / Play / QR)
kept/               coming soon
404.html            GitHub Pages serves this automatically
assets/css/         one stylesheet
assets/js/site.js   the whole motion layer (~120 lines, no dependencies)
assets/img/real/    verified real captures only — see "Imagery" below
qr/                 QR codes, regenerated by build-qr.py
tools/og-card.html  source for the Open Graph card
```

## Motion

Scroll-driven, and it degrades in two steps:

1. **Chrome/Edge** run the entry reveals from CSS `animation-timeline: view()`.
2. **Safari/Firefox** get the same reveals from an `IntersectionObserver`.

The pinned app sections publish their scroll position as a `--p` custom
property on `.pin__track`; every cross-fade, bar and tilt reads it from CSS.
With JavaScript disabled the layers simply stack in normal flow and every word
is still on the page. `prefers-reduced-motion: reduce` does the same and turns
all animation off.

## Imagery

**Only real assets.** The app icons come from each app's own repo. The one
screenshot on the site (`assets/img/real/notch-board.webp`) is a genuine adb
capture of Notch on Android, cropped, showing current branding and demo data.

Every screenshot slot is optional: the `<img>` carries an `onerror` that hides
its figure, so if a file is missing the section renders without it and nothing
breaks. Never add a mockup, a render, or an invented app screen.

## Before the domain goes live

The site is fully relative, so it works on any host as-is. Two things want the
real domain once it's bought (likely `apogeelabs.link`):

1. **`og:image` / `og:url`** in each page's `<head>` — social scrapers want
   absolute URLs. Search the pages for `og:image` and prefix with the domain.
2. **`BASE_URL` in `build-qr.py`** — the QR codes currently encode the
   placeholder domain.

## Custom domain

1. Rename `CNAME.example` to `CNAME` and put the real domain in it.
2. At your registrar, point the apex domain at GitHub Pages:
   - **A**: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - **AAAA**: `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`
   - **CNAME** (if using `www`): `<your-github-username>.github.io`
3. In Settings → Pages set the custom domain and tick "Enforce HTTPS" once the
   certificate is issued (can take a few hours).

## Regenerating QR codes

Edit `BASE_URL` in `build-qr.py`, then:

```sh
python3 -m venv .qrvenv && ./.qrvenv/bin/pip install segno
./.qrvenv/bin/python build-qr.py
```

Writes `qr/*.svg` (used on the site) and `qr/print/*.png` at 1024px.

## Regenerating the OG card

`assets/img/og.png` is a 1200×630 screenshot of `tools/og-card.html`. Edit the
template, open it in a browser at exactly 1200×630, and capture.
